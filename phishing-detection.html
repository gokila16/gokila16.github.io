Phishing detection: near-perfect accuracy, and where it breaks

Phishing classifiers trained on 215,795 websites hit near-perfect scores almost immediately. That made me suspicious, so I spent most of the project attacking them: checking for leakage, ablating features, explaining the model with SHAP, and simulating 600 evasion attempts. The result is a detector that knows where it's weak, and a two-layer ensemble built to cover that weakness.

TOO GOOD TO TRUST

No leakage. Train and test are split by domain, so the model never sees a site from a domain it was trained on. Shuffled-label runs land at AUC ≈ 0.5, which means the pipeline isn't quietly memorizing anything.

Robust, but not free. Across 15 retrains I kept removing the strongest features. Recall barely moved (99.45% with the top 14 gone), but false positives rose from 0 to 13 per 10,000.

A hidden single point of failure. SHAP showed 78% of the model's reliance sat on one URL-similarity feature. Near-perfect accuracy was hiding how narrow the model really was.

THINKING LIKE AN ATTACKER

How much effort to evade? I built a cost-weighted greedy counterfactual search that changes the cheapest features first, then ran 600 simulated attacks against each detector.

The domain is the lock. 596 of 600 successful evasions needed a spoofed domain, so the expensive thing for attackers is exactly the thing worth defending.

Who's attacking? K-means split 92,300 phishing sites into 4 attack profiles; 87% were near-empty bait pages. I turned these findings into concrete security recommendations.

THE FIX: A TWO-LAYER ENSEMBLE

One model uses every feature. The second is trained only on features that are hard to spoof. When an attacker clones a real page, the content looks legitimate, but the hard-to-fake signals still give it away.
